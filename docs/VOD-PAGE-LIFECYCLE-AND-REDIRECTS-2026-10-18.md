# 影视页面退出与订阅跳转修复

## 日志对应问题

预览 48.1 在用户离开影视页面后，VOD_BROWSE 仍完成一整轮浏览。代码核实为浏览任务由 ViewModel 作用域持有，页面销毁时只取消详情/选线任务，没有取消片库浏览；来源同步也会重启旧浏览。

订阅请求返回 HTTP 302 后，通用路由回退把它当成请求失败，尝试多个节点。旧客户端允许同协议跳转，但关闭了跨 HTTP/HTTPS 跳转，因此合法升级可能未被跟随；用户日志没有 Location 信息，不能确定该具体来源的跳转目的地或保证它已恢复。

## 修改

- 片库页面可见时才允许浏览；退出、切换到网盘文件或应用进入后台时取消该浏览请求，取消不会记录来源故障。
- 保留已加载片单；旧任务用 generation 校验，不能在取消后覆盖新结果。
- 隐藏期间来源同步仅更新配置，不重新启动片库；到期检查和迟到的网络确认回调也不能启动隐藏页面浏览。
- 返回页面仍由原有首次进入逻辑读取缓存并刷新，防止再次出现必须点“加载更多”才出内容；后台恢复时可续起被中断的请求。
- 到期的订阅文件同步与兼容性校验仍可继续。这些是配置管理任务，不等于片库浏览。验证日志使用 VOD_VALIDATE / VOD_VALIDATE_HTTP，与 VOD_CATALOG 区分。
- 资源 GET 改为显式处理 301/302/303/307/308，最多 5 次跳转、每条路由总计 30 秒；保留原有连接、读取超时及 gzip/文件大小限制。
- 允许 HTTP→HTTPS 升级，拒绝 HTTPS→HTTP 降级；拒绝无效、带凭证或循环跳转。
- 跨 origin 跳转移除 Cookie、Authorization、Proxy-Authorization、Referer；继续使用同一条已选择路由，不关闭证书校验。
- 跳转结构错误明确停止，不再循环切换代理；普通网络异常仍按原有有限路由回退。失败时原订阅缓存保留。
- 跳转日志只记录状态、次数、协议和主机，不记录 Location 全文、路径、查询参数或鉴权信息。

## 回归

新增 JVM 测试覆盖离页取消、隐藏页来源更新不重启、迟到回调被忽略、重新进入可加载及已加载片单保留；另覆盖相对重定向、同 origin 头保留、跨 origin 凭证移除、协议升级/降级策略、循环跳转不换节点、gzip 解压后限额。

真实的 HTTP→HTTPS TLS 链路和该用户订阅站尚未在设备上验证；测试包含本地 HTTP 服务与独立跳转策略测试。Android 页面回归代码只编译，没有设备执行结果。正式版和 GitHub 发布保持不变。

最终验证：236 项 JVM 测试通过（app Debug 142、core 94，失败/错误/跳过均为 0）；lint、Android 设备用例代码编译及独立预览 49.1 构建通过。完整记录见工作区 `private-audits/vod-lifecycle-preview49-final.log`。`git diff --check` 通过。预览 49.1 包含此前的跨启动频道缓存，正式版版本号未变、未推送 GitHub。
