# 影视播放可靠性与统一订阅

本地开发功能，版本号仍为 1.5.0 / 45。本轮未发布，也未推送 GitHub；沿用 Media3 原生播放器，未引入 LibreTV 网页播放器、Docker 服务或视频转发后端。

## 使用入口

- **频道源 → 影视源 → 重检**：查看来源状态、清除当前网络下的冷却并尝试读取接口。
- **点播播放页 → 连播：开 / 关**：保存自动连播偏好。有明确下一集时同时显示“下一集”。
- **频道源 → 统一影视与直播订阅 → 添加统一订阅 / 手机扫码**：输入远程 JSON 地址，导入影视接口及直播播放列表。
- **管理 N 个订阅 → 移除**：移除此订阅独占的贡献，其他订阅共享的来源及用户手动添加的频道会保留。移除不需要联网。

## 来源健康度

在真实片库加载、搜索或影片详情请求时记录结果，不在应用启动时批量探测。

同一个影视接口按所选直连 / 代理及当前 Android 网络分别记账。连续两次请求失败后暂缓访问：第一次 30 分钟，重复故障逐级延长到 2 小时、24 小时，均有到期时间，不永久停用。成功会降低惩罚等级；“重检”可提前恢复。用户取消、退出造成的取消不计为来源失败；已识别为无有效网络、不允许使用的网络，或 Android 尚未验证该网络可联网时，不记录故障惩罚。网络状态恰好变化时，仍可能存在无法完全区分的真实超时。

正常返回空搜索结果不等同于接口故障。已有片单缓存仍可浏览。加载会跳过冷却来源，并优先调度近期响应较快的接口；这只是访问调度，不等于优先选择低画质。

健康记录懒加载、异步保存，最多 200 项，过期记录七天后清理，文件保存的是来源及网络上下文的摘要，不保存完整接口地址。

## 自动连播

只匹配明确、连续的集号，例如 `第01集`、`EP2`、`03`。播放第 1 集后寻找第 2 集，不能因为某个来源缺第 2 集就跳到第 3 集。正片、全集、花絮及无法明确识别的标签不会猜测下一集。

下一集播放前重新读取影片详情并重新选线，避免复用过期直链。沿用跨来源的统一影片身份和集号标识记录续播，不按不同来源的列表下标对齐。

只在非直播媒体自然播放结束且应用仍在前台时触发自动连播；明确关闭点播、切入后台会取消待播放任务。准备失败会停留并提示，不连续跳过缺失集数。“下一集”按钮允许手动触发，自动连播关闭不影响手动选集。返回片库仍可重新选集。

## 画质与选线缓存

只检查准备播放的候选线路，最多并发 4 条、最多探测 8 条，不遍历整部剧，也不下载整集。只有一个候选时直接播放。

保留清单前缀的分辨率和可达性探测，并接入 Media3 实际视频尺寸回调：播放器测到的分辨率优先于来源标签和先前清单记录。实际尺寸只代表当前视频输出的分辨率，不证明码率、清晰度或“真 4K”画质。

缓存按临时播放 URL、所选路线及当前网络区分，有效期五分钟，最多 128 条。磁盘只保存摘要及少量测量元数据，不保存视频分片、完整直链或 token。发生媒体错误时使相关缓存失效；解码器初始化或格式不兼容等错误会在当前上下文下短暂降低该候选优先级，避免多线路时反复选中。过期或手动单线重试仍可重新验证。

排序继续以已知分辨率优先、可达性和响应耗时辅助；播放失败或长时间缓冲仍使用既有备选线路。检测范围有限，不承诺找到全网或所有来源中的绝对最优版本。

## 统一订阅 JSON

将类似内容放在自己的 HTTP(S) 地址，再在应用中导入地址：

```json
{
  "name": "我的媒体订阅",
  "version": 2,
  "sources": [
    { "name": "我的影视接口", "url": "https://example.com/api.php/provide/vod" }
  ],
  "liveSources": [
    { "name": "我的直播列表", "url": "https://example.com/channels.m3u" }
  ]
}
```

可以只提供其中一类数组。也继续识别已有 TVBox 配置中能原生读取的 JSON 接口；不会执行 JAR、JavaScript、Python 或受保护 Spider。

限制：每份订阅最多纳入 40 个影视接口及 30 个直播列表，总计最多保存 12 个订阅；合并后最多 60 个影视接口和 60 个直播列表。空或格式错误的更新不清空旧记录。新增直播列表每份最多 2000 个频道，统一订阅管理的线路总数最多 6000；超出时提示并保留原配置，不静默截断，也不改变已有手动来源。

- 同一接口 / 列表被多个订阅引用时合并展示；去掉一个订阅，不移除其他订阅仍引用的来源。
- 更新只替换该订阅的贡献，不接管同地址的手动直播列表，不修改代理订阅。
- 新直播列表先下载并解析成功，再进入数据库事务，避免网络失败先删除旧频道；失败时保留旧数据。
- 同一直播列表地址已有的启用 / 停用状态会保留；订阅将它改为新地址时会作为新列表导入。用户手动删除受统一订阅管理的直播列表后会记住所删地址，同步不自动加回该地址；用户仍可自行按普通频道源重新添加。
- 用户移除默认统一订阅后，重启不自动恢复。
- 默认沿用 24 小时到期策略，并按每个订阅独立记录时间；不增加应用启动时的全量影片或画质检测。显式导入和手动同步不必等待到期。
- 如果填写了可选 `epg` 字段，地址会作为订阅元数据保留；本轮不自动替换用户的全局 XMLTV 节目单设置。

本轮自定义统一订阅记录、健康记录、画质缓存不在原有配置备份归档内。需要迁移统一订阅时应保留自己导入的订阅地址；缓存无需迁移。

## 验证与边界

新增测试覆盖：冷却、到期、网络隔离、手动恢复、画质覆盖与失效、跨源集号和缺集、统一格式、共享归属、删除记忆、失败保留及移除全部来源后取消旧请求。

另有 Android 设备回归用例覆盖：自然结束衔接下一集、明确关闭不继续连播，以及 Room 中手动 / 停用直播列表的保留与失败更新的原子性。本环境未连接 Android 设备或模拟器；这些设备测试只能编译，不能声称已经执行通过。

外部影视接口、字幕轨、地区限制、真实网络速度和设备解码能力仍需真机验证。没有修改现有大陆、香港内置直播源，也没有增加网盘官方授权或 Spider 执行能力。
