# TVAtlas 代码与交互逻辑审计（2026-10-17）

## 范围与结论

基于正式版 v1.5.0 的本地修复分支 `fix/tv-navigation-diagnostics`，检查 Android 应用、core 模块、播放与网络链路、Room / DataStore、后台刷新、日志、构建及发布脚本。未改变版本号，没有推送 GitHub、上传 APK、修改 Release 或触发远程工作流。

这是代码及测试层面的审计，结合用户提供的电视照片；本环境没有连接电视、手机或 Android 模拟器。不能把编译通过表述为真机交互、画质、字幕翻译性能或启动卡顿已全部通过验收。

结论：确实存在可从代码确认的导航冲突、焦点抢占、布局和线程调度问题。本次修复这些问题，并补充定位电视停顿所需的日志。无法只凭照片断定“一分钟卡顿”的唯一原因；需要修复代码安装到电视后，用新日志核对。

## 页面执行与返回路径

| 页面 / 场景 | 检查的执行逻辑与当前处理 |
| --- | --- |
| 启动 | Application 建立共享日志 → Activity 创建 → ViewModel 依赖初始化 → 首次组合帧 → 本地频道数据 → 按到期策略刷新；内置频道读取和解析移至 IO，不启动节目单缓存加载 |
| 直播画面 | 遥控器确认打开频道列表；上下换台；返回打开主菜单。画面背后的播放器在频道浮层显示时不得主动请求焦点 |
| 频道列表 / 节目单 | 打开列表定位当前频道或上次焦点；确认播放，右键进入节目单。返回先关闭节目单，再关闭列表，之后可返回主菜单 |
| 主菜单 | 切换影视、频道源、代理、设置；离开直播沿用统一停止与取消待播放任务逻辑。主菜单根层返回才提示退出；取消退出仍留在主菜单 |
| 线路弹窗 | 常用播放源、频道代理优先；历史记录和高级说明折叠；内容高度依据窗口调整，减少遮挡及滚动 |
| 影视片库 | 分类 / 筛选变化触发新请求；首次进入仍沿用 44.1 的非阻塞加载修复；搜索改成顶部按钮加弹窗，清除搜索回到当前分类片单，取消输入保留原查询 |
| 影片详情 / 点播 | 返回片库并恢复影片焦点；自动选线保留高清优先及失败降级；代理客户端准备移到 IO，避免内核启动和凭证读取占用主线程 |
| 网盘目录 | 文件夹逐层返回 → 分享列表 → 影视片库 → 主菜单；修复分享列表返回时直接跳直播的路径。网盘原生播放仍受官方接入能力限制 |
| 频道源 | 保留现有源管理功能；删除没有被片库消费的来源请求变量；检查默认频道更新不丢失手动路由和播放记忆 |
| 代理 | 节点列表真正变化时才提交 core / pool 配置；测速仍在 IO、有限并发、有进度；选择标记与焦点填色分离 |
| 设置 | 手机子页先返回设置分类；电视返回进入主菜单；说明文字同步新操作规则、焦点样式和每小时到期检查策略 |
| 日志 | 电视进入“设置 → 更新与诊断 → 调试日志 → 手机扫码获取”；同一局域网手机查看、复制、下载 TXT |
| 应用后台 | 沿用 Activity 停播、暂停点播及流量 checkpoint；日志二维码在应用停止或弹窗关闭时关闭监听 |
| 更新 / 安装 | 正式渠道默认排除 prerelease 和带预发布后缀的 tag；预览版仍禁止连接正式更新渠道；保留摘要、签名、版本、资产来源校验 |

## 本次确认并修复的问题

### P1：遥控器返回层级不一致

旧逻辑使用全屏、频道浮层和 `tvBackArmed` 相互切换，某些路径直接触发退出提示。改为明确的 `LiveBackPolicy`：关闭当前浮层、返回画面、打开主菜单、根层退出。新增 JVM 策略测试。

### P1：播放器与频道列表争抢焦点

`ImmersivePlaybackLayout` 会在显示状态或播放器状态变化时主动请求焦点，即使频道浮层已经打开。新增焦点所有权开关，只允许前台画面主动获取焦点；电视确认键接到频道列表动作。新增 Android 交互回归用例，覆盖打开列表后焦点不被后台播放器取走。该用例已编译，尚未在设备上执行。

### P1：点播代理准备存在主线程阻塞路径

`prepareVodClient` 在协程主线程调用 `pool.client`，可能同步启动 Mihomo、解密节点凭证和等待本地端口。将客户端获取放入 IO。内核目录也改为实际使用时才建立。此问题是一个已确认的阻塞风险，并不能单独解释所有直播冷启动停顿。

### P1：电视缺少日志传递及早期启动证据

日志原本到 ViewModel 才建立。改为 Application 共享，覆盖主要组件初始化、Activity 创建、首个组合帧、频道库就绪、初始化阶段耗时、导航、首个按键及慢按键处理，并记录线程名。前台使用单个待处理心跳，主线程超过约 700ms 未响应时，由工作线程记录主线程调用栈，恢复后记录延迟。

扫码页面是固定快照，不自动上传；随机访问令牌、绑定 LAN IPv4、五分钟有效、只读固定路由、禁止任意文件读取和修改。支持纯文本、TXT 下载、浏览器复制和复制失败时手动选取。关闭窗口或应用进入后台时关闭会话。日志继续脱敏，不记录完整地址、认证标头或响应正文。

### P2：启动及数据更新存在重复工作

- 内置地区表延迟读取并在 IO 中解析、保存。
- 节目单缓存只在选台或用户手动刷新时读取，不在启动时加载。
- 原 15 分钟检查改为每小时检查；实际刷新仍按照设置到期时间，默认 24 小时；点播和直播播放时均跳过自动刷新。
- 节点列表未变化时，不再对频道库的每次变化重复提交代理配置。
- 频道保存时建立 ID、名称、播放流身份索引，避免逐条扫描全部旧播放流；只写入实际变化的频道和播放流，减少 Room 通知与重组。
- 台标预缓存延后 1.5 秒，下载之间小幅让出时间；仍保留本地台标及磁盘缓存。
- 日志增量维护字节长度，避免每条事件重复编码全部历史记录。

### P2：焦点样式与已选状态混淆

电视按钮使用随焦点移动的填色；频道、卡片使用填色提示；下拉项和图标按钮补充同类反馈。已选页面 / 配置保留侧边标记，正在播放频道保留播放标记，移除源卡片和代理节点的重复紫色使用中底色。同步帮助文案，取消“白框为焦点”的旧说明。

### P2：影视海报、搜索栏挤占内容空间

取消片库常驻大搜索输入框，改为顶部按钮与输入弹窗；搜索期间显示紧凑状态及清除入口。电视 / 宽屏卡片按可用宽度排 3–7 列，使用更矮的裁切封面与固定两行片名；手机保留较窄网格。长说明和影视详情仍独立滚动，不扩大海报占用。

### P2：正式更新渠道混入预发布

原更新读取器仍保留早期测试渠道兼容行为。本次默认只接受正式发布，预发布解析仅由显式测试参数启用；新增回归测试确保不请求被排除的预发布清单。没有进行任何实际发布。

## 保留的正确行为

- 直播离页会取消待解析线路并停止播放器，避免后台继续播放或迟到的网络结果重新启动直播。
- 节目单解析、媒体请求、测速、备份加解密和凭证保存已有相应后台路径；没有把安全相关持久化 `commit` 随意改为不确认落盘的 `apply`。
- 片库聚合保持有限并发、请求代次和旧结果隔离；原 44.1 的首次进入请求修复保留。
- 点播网络默认直连；保留手动代理选择和高清优先，未改动订阅地址或已有大陆、香港频道。
- 翻译继续使用独立文本字幕；不把视频内嵌文字当作可关闭或可翻译的字幕，也不取消设备性能准入要求。
- APK 及发布流水线校验保留；发布脚本测试使用模拟网络写入，没有上传文件。

## 后续建议及未验证边界

1. **电视冷启动复测（优先）**：冷启动、热启动各做三次，记录首次按键能响应的时间。取得 `STARTUP_COMPONENT`、`STARTUP_DEFAULTS`、`STARTUP`、`MAIN_STALL`、`MAIN_RECOVERED` 和 `INPUT_SLOW`，再决定是否继续拆分启动任务；当前不保证卡顿已在所有设备上消失。
2. **遥控器真机验收**：直播连续执行确认 / 返回 / 菜单 / 长按；从影片详情、网盘多层目录、设置子页返回；验证当前焦点不会被异步播放状态抢走。当前只完成测试代码编译，未执行设备 UI 测试。
3. **布局验收**：至少覆盖电视 960×540dp、低分辨率盒子、大字体、平板横屏和手机竖屏；确认当前卡片及两行片名完整可见。当前没有本次修改后的运行截图。
4. **翻译与外部源**：语言包下载、真实字幕轨、热状态、设备 CPU / 内存、第三方地域与授权限制都需要设备或网络场景验证，不能凭单元测试给出全量可用结论。
5. **可维护性**：`PlayerApp`、`PlayerViewModel` 仍同时承担多项职责。建议后续分拆根导航、弹窗协调、播放与订阅服务，并统一管理请求生命周期；本次只提取明确的返回策略、启动诊断和日志分享组件，避免在缺少真机回归时做大规模结构改写。
6. **平台 API 与依赖提示**：仍有旧 Clipboard API、网络枚举 API 及依赖升级提示。不是本次已确认卡顿的证据；后续升级应单独验证 Android 版本、遥控器和播放兼容性。
